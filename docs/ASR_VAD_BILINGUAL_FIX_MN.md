# BYBE — Холимог Чех/Англи ярианы ASR засвар v2 (2026-11-15)

## Сайн ажиллаж байгаа мэт харагдсан боловч буруу байсан зүйлс
- Анхны Python worker `BYBE_ASR_MODEL=small`, CPU `int8`. Энэ нь Subtitle Edit дээр хэрэглэж байсан `large-v3` биш.
- 5 минутын бүх аудиод `language=None` өгч, Whisper нэг л хэл сонгоод Чех/Англи ээлжилсэн хэсгийг нэг хэлээр тайлбарлах эрсдэлтэй байсан.
- `vad_filter=True`-ийн үндсэн 2,000 мс silence хугацаа үг/орчуулга/давталтын богино завсарт хэт урт.
- `src/lib/autoAlign.ts` 5 минутын 1,200 peak-ийг OCR текст дээр таамгаар тавьсан (250 мс/цэг). Энэ нь жинхэнэ яриа таних, word alignment БИШ.

## Зассан
1. `scripts/local_asr_worker.py` — бүтэн 5 минутын ангиллын оронд эхлээд Silero VAD (`min_silence_duration_ms=350`, `speech_pad_ms=110`, `max_speech_duration_s=15`) хийж, тус тусад нь `WhisperModel.transcribe(...,language=None,word_timestamps=True)` ажиллана. Чех/Англи хэл чанга солигдохад илүү тохирно; 1 богино utterance дээр хэлийг буруу таньж болох учраас мөн review шаардлагатай.
2. JSON дээр `languageScope=utterance`, `asrPass=VAD_UTTERANCE`, `reviewReasons`, `languageProbability` ба `words` хадгална. Хүнд цаг/хэл/үг таарч буй мэт худал баталгаажуулахгүй.
3. `src/StudioWorkspace.tsx` — хуучин 5 минутын ASR ба OCR+waveform гэнэн таслалтыг үндсэн жагсаалт, waveform-д анхдагчаар харуулахгүй. **Огт устгахгүй**, JSON backup хэвээр. `Хуучин/таамаг` товчоор нээнэ. Бүдүүн energy+OCR таамгийг шинэ видеонд анхнаасаа цувуулж гаргахгүй.
4. Хуучин ASR job автоматаар солигдохгүй. `Хэрэгслүүд → Шинэ VAD танилтаар дахин шалгах` товч хуучин ажил дууссан үед шинэ job үүсгэнэ. Өмнөх job болон гараар баталгаажуулсан QA/WAV-г дарж бичихгүй.
5. CPU ажиллуулалтын урсгал `BYBE_ASR_CPU_THREADS=4` (тохируулж болно) — OCR, browser-ийг түгжих эрсдэлийг багасгах; илүү нарийвчлалын баталгаа биш.
6. `START_BYBE_QUALITY.bat` — `medium` model-ийг CPU int8 дээр сонгох, анхны удаа интернетээр үнэ төлбөргүй модель татах, өмнөх `small`-аас удаан, магадгүй илүү зөв. GPU-д `CUDA` сан байхгүй бол хүчлэхгүй.
7. /api/asr/status болон BYBE status line — одоогийн модель `small / medium`, `cpu / cuda` гэж бодитоор харуулна.

## Windows туршилт — хэрэглэгчийн өгөгдлийг хамгаалах
1. Хуучин BYBE дээр `Бүртгэл экспортлох` → `BYBE_...json` backup-ийг Downloads-оос өөр хавтас руу хадгал.
2. Хуучин CMD серверийг Ctrl+C нэг удаа зогсоо. Доорх командыг нэг удаа ажиллуул:
   ```bat
   cd /d D:\bybe-studio\BYBE-new
   git pull origin feature/typography-ocr-workstation
   ```
3. Эхлээд `START_BYBE.bat` (хурдан `small`) эсвэл зөвхөн жижиг 1–3 минут туршихдаа `START_BYBE_QUALITY.bat` (илүү удаан `medium`) хоёрын нэгийг давхар товш.
4. Видеогоо дахин нээ. `Хэрэгслүүд → Шинэ VAD танилтаар дахин шалгах`. CPU хурд видео болон загвараас хамаарна, эцсийн чанарын баталгаа биш.
5. Эхний хоёр үг ба нэг бүтэн өгүүлбэрийг ▶ сонсож, Чех/Англи текст, эхлэл/төгсгөлийн яг зааг, дараагийн үг рүү давсан эсэхийг шалга. `✎ Audio Vision`-ийн заагийн санал нь хүний QA орлохгүй.
6. Хэрэв шинэ VAD санал муудсан бол `Хуучин/таамаг` товчоор өмнөх raw мөрүүдээ буцааж харж болно, JSON backup-аас бүртгэл импортолж болно.

## Хязгаарлалт
- VAD нь хэл танихгүй, зөвхөн ярианы идэвхтэй хэсэг олно.
- `language=None` нь **богино** нэг үг дээр алдаа өгч болно; Чех/Англи бичвэр ба аудио зааг QA зайлшгүй.
- 350 мс нам гүмгүй дараалсан Чех+Англи яриа нэг VAD хэсэгт үлдэж болно. `medium` загвар ч үүнийг 100% шийдэхгүй.
- Шинэ ASR/таслалтын чанар бодит user-verified PART004 дээр хэмжигдээгүй. GitHub-ийн synthetic тестүүд програм алдаагүй ажиллахыг шалгадаг боловч бодит ярианы accuracy-г батлахгүй.
- Дараа нь screenshot OCR текст + phoneme alignment (Чех хэлний forced aligner) ашиглах нэмэлт шат шаардлагатай.
